# Evidence, логи и история

Это правила хранения, не новые проверки продукта. Инвентаризация02.10 не удаляла
данные исполнения, fixtures, evidence или сырые логи.

| Где | Что хранится | Как использовать |
|---|---|---|
| docs/CURRENT_CONTEXT.md | Короткое актуальное состояние | Читать первым; обновлять по состоянию |
| docs/ROADMAP.md | Очередь тестового этапа и отдельный боевой | Не вести второй журнал |
| docs/IMPLEMENTATION_STATUS.md | Карта кода | Обновлять при изменении реализации |
| docs/PRODUCT_SPEC.md | Принятые правила | Только новые продуктовые решения |
| docs/*модуль*.md | Технический контракт/границы | Актуальное резюме сверху, датированные результаты отдельно |
| docs/evidence/ | Воспроизводимые результаты, receipts, source hashes | Могут читаться тестами; не перемещать как мусор |
| test/fixtures/, research/ | Входные данные и исследования | Сохранять версии/происхождение, смотреть ссылки из кода |
| docs/archive/ | Старые планы, ревью и снимки | История, не инструкция к следующему действию |
| .local/logs/ | Сырые логи, временные отчёты и исследовательские helpers | Не читать целиком при старте; не считать любой RUNNING файлом PASS |
| .local/ вне logs | Локальное состояние, journals, locks и окружение | Не чистить вместе с документацией |

## Как фиксировать завершённый пакет

В отчёте: дата, задача, commit/dirty state, команда и объём проверки, результат,
ограничения, ссылки на evidence. В контексте — одна ссылка и актуальный остаток работы.
PASS частичного профиля не является full baseline. Synthetic funding/finality,
mock wallet, fork и реальная публичная транзакция — разные уровни доказательства.

Переходные попытки и failures остаются в истории; подтверждённый результат выделяется
явно. Завершённые GPT request/response архивируются, текущие файлы показывают статус.

## Уборка02.10

128 верхнеуровневых Markdown документов классифицированы в [каталоге](DOCUMENT_CATALOG.md).
Прежние версии изменённых документов сохранены со ссылками и хешами в
[снимке](archive/context-2026-10-02/README.md). Байтовое содержимое оригиналов
доступно в raw-подкаталоге снимка; readable copies отличаются статусом и относительными ссылками.

Сырые .local/logs сохранены на прежних путях: некоторые scripts/tests/reports ссылаются
на них, а рядом находятся промежуточные configs/receipts. Файлы не переносились и не
удалялись. Локальная опись размеров/типов и ссылок —
`.local/logs/docs-artifact-inventory-20261002.json`. Она не доказывает пригодность каждого
файла и не публикует содержимое журналов. Для будущего удаления сначала нужен поиск
зависимостей и выделение воспроизводимого evidence, а не удаление по возрасту.
