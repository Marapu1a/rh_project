## API

- `register()` регистрирует только `msg.sender` и публикует `Registered(participant)`.
- `registered(address)` возвращает текущее состояние участия.
- Повторный вызов отклоняется с `AlreadyRegistered`; первое событие не заменяется.

Нет owner, регистрации третьего лица, удаления/перезаписи записи, обновления контракта, внешних вызовов или приёма оплаты. Газ оплачивает вызывающий. Контрактные кошельки могут регистрироваться: сохраняется адрес кошелька-контракта, не `tx.origin`. Если пользователь вызывает registry через произвольный посредник, регистрируется именно посредник; frontend должен вызывать register непосредственно от участвующего кошелька.

Один registry соответствует одному экземпляру промо. Адрес registry входит в будущий deployment/snapshot context; контракт не знает TOKEN/PromoVault и сам не выдаёт попытки или право на приз. Второй deployment не наследует регистрации первого. В этой версии регистрация одноразовая, функции unregister нет; правила действительности покупок остаются отдельными.

## Историческая граница

Точка вступления — каноническое событие регистрации. Покупка должна следовать после него по порядку `(blockNumber, transactionIndex, logIndex)`. Block timestamp или текущего bool недостаточно: покупка раньше регистрации в том же блоке не получает ретроактивное право на билет.

При reorg отброшенная регистрация также исчезает. Indexer обязан откатывать зависимые вычисления и повторно читать каноническую историю; этот контракт не реализует off-chain reorg handler. В [replay v1](DIRECT_BUY_REPLAY.md) событие BUY — канонический PoolManager Swap log; новая ветка полностью пересчитывается от anchor. Production finality ещё не определена.

## Проверки и границы готовности

`npm run test:registration`: шесть тестов — самостоятельное вступление и событие, повтор, восстановление истории, smart wallet и события до/после регистрации внутри одной транзакции, изоляция экземпляров/API, откат локальной цепочки и повторное вступление. Маркеры покупок в fixture проверяют только порядок логов, не PAIR BUY decoder.

`npm test` включает новые и существующие контрактные тесты. Регистрация подключена к [decoder/replay v1](DIRECT_BUY_REPLAY.md); frontend и production controller отсутствуют, публичного deployment нет. Это готовый небольшой компонент, а не реализация всей архитектуры снимков.
