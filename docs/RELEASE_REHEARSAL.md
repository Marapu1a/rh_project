# Составная репетиция перед запуском

Одна команда из корня проекта:

```powershell
npm run rehearsal:release -- .local/logs/release-rehearsal.json
```

Выходной файл должен быть новым. Без аргумента создаётся файл с timestamp в
`.local/logs`. Ошибка проверки даёт exit code 1 и отчёт `failed`. Успешное выполнение
даёт `complete`, но всегда `publicLaunchReady:false`. Это не публичный deployment.
Команда не использует внешний RPC и приватные ключи пользователя. Локальная цепочка
создаётся in-process; записи в существующий runtime проекта не делаются.

## Что проверяется вместе

1. Реальные сохранённые Infinity fork receipts пересчитываются существующим BUY
   decoder. Повторная доставка блоков не удваивает билеты. Получаются два билета.
2. Эти участники явно переносятся в отдельную локальную цепочку 4663. Разворачиваются
   обычные Robinhood контроллеры и drand adapter, без изменения Solidity-исходников.
3. Fixture creator source получает 2006 USDG; общий worker забирает доход и распределяет
   90/5/5. Проверяется сумма призового баланса, credits и уже выплаченных ops/project долей.
4. Из перенесённых участников helper готовит Short и Monthly datasets и замораживает их.
   Далее source намеренно перестаёт работать. Общий runtime остаётся в obligations-only,
   проводит BLS prove/deliver, settlement и выплату реальных локальных USDG.
5. У первого claim искусственно теряется ответ ожидания receipt. Следующий вызов worker
   читает тот же checksummed journal, сверяет известный hash и завершает выплаты.
6. Сумма выплат плюс оставшийся призовой баланс совпадает с первоначальным; frozen и
   claimable пусты. Ещё один запуск не меняет nonce исполнителя и балансы победителей.

## Где граница доказательства

Это **составная проверка**, не непрерывная история одной сети. BUY использует сохранённые
настоящие транзакции; текущий запуск их не отправляет и не перечитывает из сети.
Публикация datasets и freeze в локальной части выполняются helper, а не автоматическим
индексатором по тем же on-chain BUY. Перенос участников виден отдельным этапом отчёта.

ArbSys, USDG, внешний creator source и venue state — fixtures. Применены виртуальное
время и историческая drand подпись с настоящей BLS проверкой. Шансы почти гарантируют
выигрыш, корзина 7/5/3 и бюджет Short 100 USDG — тестовые значения, не релизное решение.
Рестарт — новый вызов worker с перечитыванием журнала на живом локальном узле,
не OS kill и не восстановление после потери самого узла.

Реальная operations конверсия уже проверена отдельным fork. В новый отчёт включены
ссылка, хеш и исходная высота этого evidence; рынок не запускается заново и не
выдаётся за часть текущей цепочки. Локальные gas fees не являются оценкой Nitro.

## Профиль и отчёт

[Профиль репетиции](../config/release-rehearsal.json) содержит таблицу параметров
со статусом и источником. Принятые значения сверяются с
[публичным launch plan](../config/robinhood-launch-plan.json). Его null-поля не
заполняются локальными адресами. Репетиция не принимает продуктовые решения за владельца.

Отчёт содержит SHA256 входов, хеш compiled artifact, deployment pins, данные replay,
оба draw IDs, pending/receipt, начальные/конечные балансы и копии журналов. При сбое
сохраняется stack ошибки; `complete` означает прохождение перечисленных проверок.

## Конечный список оставшихся ворот релиза

- Прогон одной цепочки: admitted BUY → автоматические datasets → оба draw, с рабочим
  расписанием и без переноса участников между средами.
- Пригодный archive RPC и резервный endpoint.
- Реальные deployment адреса/роли, source/immutable verification и утверждённые
  призовые, временные и gas параметры. Конкретные null-поля перечислены в отчёте.
- Публичное исполнение после квалификации; текущий запрет отправок сохраняется.
- Постоянный индексатор и сайт: билеты, условия, результаты, claims.
- Сервис: ключи, устойчивое хранилище, мониторинг и инструкция восстановления.
- Воспроизводимая сборка/CI, verification исходников, условия промо и внешний аудит.

Дальнейшая работа идёт по этим пунктам. Новые механизмы funding, RNG или призовые
правила в эту репетицию не добавляются.

## Проверка повторяемости после review

[Разбор lock](REHEARSAL_LOCK_INVESTIGATION.md): исходный Windows и три усиленных
прогона (Windows/Linux9p/Linuxext4) complete. GPT сообщает EEXIST в своей среде;
причина не подтверждена, нужен его полный failed report + trace. Это не объявлено
исправлением lock-механизма.

Теперь complete дополнительно требует двух уникальных `(drawId,winner)` sends,
успешных receipts и RewardPaid с точными суммами terminal результатов, нулевых
оставшихся rewards и совпадения прироста кошелька с суммой обеих наград. При ошибке
в отчёт попадают ответ resume worker и snapshot файлов до test cleanup; туда же
записывается Node/OS/runtime filesystem. Обычный запуск не обходит существующий lock.
