# Кабинет и Claim — тестовый пакет 02.10.2026

## Что подключено

- Buy открывает внешний Pons `/launchpad/<token>`, а не наш торговый терминал.
  Адрес берётся только из явно заданного `publishedMarketToken`. Без него остаётся
  честное «buy link coming soon»: боевой QIANQI этим пакетом не создаётся.
- Кабинет сохраняет существующий EIP-6963/EIP-1193 выбор провайдера и аккаунта.
  MetaMask не является требованием. QR/WalletConnect этот пакет не добавляет.
- API показывает билеты, остаток накопления, frozen tickets, призы/выплаты и теперь
  последние 25 атрибутированных покупок. Отсутствие строки не считается отказом.
  `ELIGIBLE` — засчитано, `INELIGIBLE` — не подходит, `UNSUPPORTED_ROUTE` — маршрут
  пока не поддержан, `AMBIGUOUS` — не удалось подтвердить. Исходный reason доступен
  в раскрываемой детали. Весь список/пагинация пока не подключены.
- Claim — ручной запасной путь выплаты уже назначенного приза. Вызов
  `claim(drawId, selectedAccount)` отправляет средства победителю; token approval,
  перевод ETH и выбор стороннего получателя отсутствуют. Газ оплачивает вызывающий.

## Граница безопасности и окружения

`web/claim.js` — общий модуль для браузера и адресных тестов; ethers 6.17.0 сохранён
локально с MIT-лицензией в `web/vendor`. CDN не используется. Сервер сайта по-прежнему
только читает API/файлы; ключей, подписанта и endpoint отправки транзакций у него нет.

Включение действий **только на loopback и chainId 31337**. Настройка:
`RH_SITE_ACTIONS_FILE=<локальный JSON>` перед `npm run site`, либо `createSite({actions})`
в тесте. `/site-actions.json` отдаёт null без конфигурации. Формат:

```text
schema: qianqi-site-actions-v1
mode: local-test
chainId: 31337
vault, asset: адреса конкретного тестового deployment
vaultCodeHash, assetCodeHash: keccak256 развёрнутого runtime
decimals: точность тестового призового актива
anchor: {number, hash} блока этого deployment
publishedMarketToken: необязательный проверенный адрес рынка для внешней ссылки
```

Не подставлять вымышленные deployment-адреса. Тест самостоятельно создаёт реальные
локальные vault/token; prize assignment делает fixture-controller, API-витрина
в браузерном тесте синтетическая. Это не новый сквозной прогон индексатора и RNG.
Mainnet 4663 отвергается модулем, даже если JSON назван local-test. Публикация и
боевые deployment bindings требуют отдельного этапа.

Перед просмотром/отправкой проверяются выбранный account, chain, deployment anchor,
runtime обоих контрактов, quoteToken, finalized draw и точная невыплаченная сумма.
Далее `eth_call` и оценка газа. Перед send проверки повторяются: если автоматическая
выплата уже прошла, вторую транзакцию не создаём. Смена аккаунта/сети или обновление
снимка инвалидирует открытое подтверждение. Кошелёк всё равно требует своего согласия.

Claim показывается только для fresh API, совпавших vault/asset/decimals и победителя.
Задержка или недоступность данных не превращается в нулевой баланс и не разрешает Claim.

## Pending / восстановление

До обращения к кошельку записывается localStorage journal, привязанный к chain,
anchor, vault, draw и winner. Web Locks защищает вкладки одного origin. Если storage
или Locks недоступны, отправка закрыта. Разные устройства/origin не разделяют журнал;
контракт остаётся окончательной защитой от двойной выплаты.

4001 позволяет повторить отклонённый запрос. Остальные ошибки после send — unknown,
без автоматического повтора. Неразрешённый wallet promise тоже остаётся submitting;
перезагрузка не превращает его в новый запрос. Поздний hash сохраняется для исходного
аккаунта, даже если пользователь уже переключился.

«Claim / check payment» сверяет receipt с каноническим блоком, отправителем,
получателем, calldata и нулевым value; успешный receipt также требует reward=0.
Reverted позволяет повторную preflight-проверку; pending/unknown не повторяется.
Unknown без hash требует сверки активности кошелька; автоматического reset или
ручного импорта hash в этом пакете нет. Не очищать browser storage ради повтора.
Статус confirmed здесь означает канонический receipt на локальной цепочке, не
доказательство finality публичной сети. Индексированное Paid обновляется отдельно.

## Проверка

Команды и результаты текущего рабочего дерева (не полный release baseline):

- `node --test web/claim.test.cjs` — реальный локальный vault + Chromium,
  отказ/unknown/restart, поздний hash, смена выбранного аккаунта, pending/неверный
  receipt, anchor/runtime guards, гонка с автоматической выплатой, отказ storage.
- `node --test web/site.test.cjs web/wallet.test.cjs web/overview.test.cjs` — соседние
  проверки кабинета, нескольких провайдеров, аккаунтов, сетей и stale/unavailable.
- Browser provider — EIP-6963 fixture, передающий запросы реальному Hardhat EVM.
  Установленное расширение MetaMask/Rabby этим не проверено; это следующий ручной
  контрольный прогон в согласованной локальной сети, без реальных средств.

Результат: 3/3 исходных сценария PASS; после усиления проверки receipt —
3/3 адресных сценария (`HK browser|late wallet|unresponsive read`) PASS; соседние
19/19 PASS. Это частичные проверки, не полный baseline. Тест перенесён из
`test/site-claim.test.cjs` в `web/claim.test.cjs`, к остальным browser tests.

Логи: `.local/logs/site-claim.log`, `.local/logs/site-claim-final.log`,

## Ручной прогон с расширением

`node scripts/site-wallet-rehearsal.cjs --wallet <публичный адрес>` поднимает
одноразовый in-memory Hardhat 31337, loopback RPC18545, призовую API-витрину18787
и сайт4174. Сначала выполняется контрольный browser Claim с отдельным случайным
тестовым ключом через **подписанную raw transaction и HTTP RPC**. Ключ не записывается.
Если smoke не прошёл, процесс завершается; успешный результат и публичные адреса
сохраняются в `.local/logs/wallet-rehearsal.json`.

На выбранный адрес начисляются локальные 10 ETH для газа и два приза: 70 и30
тестовых USDG (6decimals). Призы действительно назначены локальным vault; read API
читает текущий reward из контракта. Билеты/покупки в этой отдельной витрине пустые,
overview не моделируется. Это прогон кошелька/Claim, не всего индексированного цикла.
После остановки процесса цепочка исчезает. Перезапуск создаёт новый anchor и journal scope.

не потрачены. Проверены запреты `hardhat_reset`, unsigned `eth_sendTransaction`,
