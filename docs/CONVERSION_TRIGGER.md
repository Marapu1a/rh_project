# Конвертация по ожидаемому пополнению Short

Решение пользователя 24.09.2026: точный курс и сумму обмена не обещаем.
Бот наблюдает net котировку конкретной ограниченной порции TOKEN (после fee/impact).
Когда ожидаемое пополнение достигает Short target, появляется кандидат на обмен.
Сохраняются minOut/deadline и ценовая защита. После receipt учитывается фактический USDG.
Если его недостаточно — он остаётся в резервах, накопление продолжается.
Призы фиксируются по имеющимся средствам; интервалы и другие draw gates сохраняются.
GENERAL распределяется по прежним правилам: вся сумма продажи не равна Short-доле.
Frozen/claimable не входят в freeShort. Спонсорское funding может закрыть target без swap.

## Реализовано

`scripts/short-conversion-trigger.cjs`: чистый planner, raw bigint суммы, проверка
размера порции/давности quote и прогноз Short с учётом generalFundingPhase.
Нет RPC, подписанта или назначения цены. candidate не авторизация swap и не draw readiness.
`node --test test/short-conversion-trigger.test.cjs`: 4/4, включая funding split
для всех фаз, stale/limits и достаточную quote при недостаточном фактическом результате.
Это unit-проверки, не EVM/fork интеграция.

## Что ещё не подключено

Старый prize-flow worker пока продаёт при наличии inventory по fixed-floor ABI.
Planner ещё не меняет его поведение. Следующий пакет: quote/bindings на согласованном
snapshot, новый converter ABI/version, повторная проверка перед отправкой, minOut,
receipt recovery и чтение фактических резервов. Выбор источника price guard не закрыт;
этот триггер его не заменяет. Никакого fallback на spot или отключения защиты не принято.
target и пределы не утверждены числами. Если ограниченная порция не закрывает target,
planner ждёт: стратегию нескольких продаж нужно проверить отдельно, лимиты не расширять.
Monthly этим шагом не меняется.

Для сайта: amountIn, фактический amountOut/курс, время/hash транзакции и пополнение
резервов. UI ещё не реализован. Не показывать quote как обеспеченный выигрыш.
