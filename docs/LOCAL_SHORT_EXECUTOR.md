## Вход и API

`scripts/local-short-executor.cjs` экспортирует:

- `makeJob(artifact, proposalId, chunkSize=64)` — JSON-совместимый job с checksum.
- `stepShort({provider, source, job, publisher, executor, gasPrice})` — читает цепь,
  проверяет привязки и выполняет максимум одну транзакцию.
- `runShort(options, {maxSteps=128, onStep, signal})` — последовательно вызывает step
  до ожидания, завершения, остановки или лимита шагов.

Artifact формируется существующим `buildFromHistory`/CLI из проверяемой BUY-истории.
Job содержит artifact, proposalId и размер публикационной порции. Он не содержит seed,
private key, следующего nonce или локального номера обработанного chunk.
Checksum обнаруживает случайную правку job, но не является подписью или proof of history.
Полнота исходной истории остаётся прежней границей доверия publisher/replay.

Прогресс определяется только по контракту: начатое предложение, опубликованный префикс,
статус seal, сохранённый seed, nextChunk и terminal. Порции после seal восстанавливаются
из публичного calldata; новый исполнитель может продолжить без локальной базы предыдущего.

## Действия

| Состояние | Поведение |
|---|---|
| Предложения нет | Проверка job/deployment/cutoff/policy, ожидание расписания/роли или begin |
| Publishing | Сверка request и опубликованного префикса; публикация следующей порции |
| Ready | Полный verifyPublication, readiness и симуляция seal; reserve/request одной транзакцией |
| WaitingSeed | Только ожидание; нет seed delivery, replacement, timeout/no-win |
| Processing | Recovery из цепи, следующая порция; перед finish сравнение resultHash с независимым расчётом |
| Terminal | Проверка результата, выход без транзакции |
| Superseded / неверный job | Явная ошибка; самостоятельная замена job запрещена |

Publisher нужен только для begin/publish. Seal/process/finish выполняются executor.
Нет вывода призов, ручного назначения победителей, claim за пользователя или смены правил.
Выбор новых draws и построение нового cutoff после завершения — задача следующего слоя.

Readiness использует fee cap при симуляции. Все отправки ограничены maxGasPrice
контроллера; типизированные EIP-1559 транзакции сохраняют явный chainId в локальной
RPC-истории. Это локальная эксплуатационная политика, не production gas estimation.

Недостаток prize funding определяется симуляцией настоящего seal: она включает
признание direct USDG. Чтения одного freeShort недостаточно — деньги могли уже
поступить напрямую, но ещё не попасть в признанные резервы.

## Остановка, ошибки, гонки

Waiting возвращает причину: publisher/executor, schedule, cutoffDelay, otherDraw,
executionReadiness, prizeFunding, gasPrice, pendingTransaction или seed.
Ожидание не меняет job и не расходует попытки. Старый cutoff до begin, вышедший за
256 блоков, требует явно пересобрать незамороженный job; worker этого не делает.
После begin возраст cutoff сам по себе не мешает завершать публикацию/расчёт,
но его hash по-прежнему должен быть каноническим.

При незавершённой транзакции выбранного signer новые отправки приостанавливаются.
RPC/send/receipt errors выходят наружу, без автоматического rebroadcast и выбора nonce.
После восстановления связи запускается тот же job: цепь определяет, что уже произошло.
SIGINT останавливает цикл между действиями; уже отправленная транзакция не отменяется.

Это не distributed queue и не гарантия отсутствия повторной оплаты газа при гонке
нескольких процессов. Дублирующие изменения блокируются контрактом, но проигравшая
транзакция может revert. Нет durable mempool journal, replacement policy, RPC failover
или production finality. Full verification на каждом шаге намеренно простое и затратное;
масштабирование reader/кэширования остаётся отдельным этапом.

## Запуск

Сначала на локальном узле должны существовать deployment и job, построенный под него.
Job от другого запуска/ветки/контроллера не подойдёт. ABI берётся из локального
`artifacts/compiled.json` (`npm run compile`). CLI использует только unlocked accounts
loopback HTTP RPC; не читает ключи и не подключается к публичной сети.

```powershell
npm run local:short -- --job .local/short-job.json --rpc http://127.0.0.1:8545 --publisher 0 --executor 1 --watch
```

Без `--watch` выполняется доступная последовательность до первого ожидания/terminal
или лимита шагов. С `--watch` повторное чтение начинается через секунду; ошибка
останавливает процесс с ненулевым exit code. Для только публичных действий publisher
не указывается. Каждое действие/состояние печатается одной JSON-строкой.

`npm run test:local:executor` — полностью автономный локальный тест двух BUY-циклов:
разворачивает стенд, строит job из истории, прогоняет worker и закрывает стенд.
Это тот же расширенный BUY-cycle test, а не дополнительный дубликат в основном наборе.

## Проверяемые сценарии

- Перезапуск с JSON job между begin, отдельными publish/process и finish.
- Чужой publisher, изменённый job, неверный controller/chain не отправляют транзакцию.
- Provider not ready, высокая цена газа, недостаток prize funding и ожидающая
  транзакция signer; прямое пополнение разблокирует seal.
- Request failure не оставляет frozen budget; тот же job продолжается после восстановления.
- Повтор ожидания seed не создаёт новый request; смена исполнителя сохраняет progress.
- Реальные terminal-события возвращаются в BUY replay; Short расходуется, Monthly сохраняется.
- Reorg terminal → повторное завершение с тем же seed; повтор terminal не отправляет tx.
- Отдельный CLI-процесс читает сохранённый завершённый job и выходит без отправки.

Новый RNG не реализован: тестовый провайдер по-прежнему подаёт контролируемый seed,
чтобы проверить выплату. Worker не выбирает и не доставляет этот seed.

## Ограниченное ожидание транзакции

Receipt ожидается не дольше 30 секунд; library option `receiptTimeoutMs` допускает
1–300000 ms. Timeout завершает запуск с ошибкой и hash транзакции; автоматической
повторной отправки нет. AbortSignal/SIGINT прекращает ожидание, но отправленная
транзакция всё ещё может подтвердиться. Перед повтором проверить её состояние;
после подтверждения worker продолжает с on-chain progress. Это не durable mempool journal.

До begin проверяется возраст cutoff в предполагаемом следующем блоке: текущий
возраст 255 ещё допустим, 256 уже отвергается. При задержке включения окончательную
проверку всё равно делает контракт. Регрессии: `npm run test:local:stability`.
