# Сравнение настроек Short: 5 760 недельных прогонов

> Статус после решения 14.09: Luck удалён из продукта. Ниже сохранено исследование на момент его проведения, а не текущие правила. Основная модель — `short_model.py` без Luck; исторические сравнения используют `short_model_legacy.py`. Актуальные правила — [PRODUCT_SPEC](PRODUCT_SPEC.md).

14.09.2026. Исследование на локальной модели, без сети, контрактных изменений или принятия production-параметров.

## Условия сравнения

20 seeds (20260914–20260933), шесть типов потока, два внешних стартовых банка ($0/$400 GENERAL), K=5/10/20, h_e=3/1 и три бюджетных режима. Основная сетка — равные веса с минимумом $5 на место, чтобы отделить эффект K от формы корзины. Дополнительно — 10 мест с весами [7,5,2,2,1,1,1,1,1,1], минимумом базовой единицы $5 и бюджетом готовности $110.

Каждый seed задаёт одни и те же покупки, продажи и начальные carry для всех сравниваемых политик. Поток материализуется независимо от RNG розыгрышей; seed исхода привязан к времени события, а не к числу предыдущих вызовов. Разные политики могут дать разные cohorts и последовательности случайных решений — это сравнение моделей, не принудительно одинаковые победители.

60 кошельков: неодинаковые покупки, активное ядро и эпизодические покупатели. Начальный carry — синтетические исторические покупки, не доход текущей недели. В ledger отдельно проверяется initialCarry + newBUY = createdEntries * $100 + remainingCarry. Самих старых готовых attempts и начального Luck нет. Все покупки eligible; BUY/SELL не моделируют движение цены, происхождение монет продавцов или прибыль трейдеров.

Сценарии:

- steady: $20 000 общего оборота в сутки, BUY 60%, семь дней;
- decay: $40k → $30k → $20k → $15k → $10k → $5k → $2k, доля BUY снижается;
- whale: $20k/сутки, намного большая доля покупок у одного кошелька;
- stop: $40k → $10k → 0 → 0 → 0 → 0 → 0;
- low-fee-delay: $20k/сутки, эффективный доход вдвое меньше и поступает с задержкой 12 часов;
- rich: $200k/сутки — проверка избытка funding.

Effective creator USDG revenue условно 0,5% оборота (0,25% в low-fee-delay), проекту 10%, призовая часть по кандидатным 3:2:1. Next ограничен $100. Это **не проверенные ставки PAIR**. Операционные затраты и monthly random не моделируются; недельное окно не доказывает долгосрочную устойчивость. Шаг событий 6 часов. Денежные награды фиксируются как claimable, предполагаются обеспеченными, но фактическое получение здесь не моделируется: поле `paid` JSON означает сумму назначенных наград, не подтверждённые on-chain выплаты.

Все режимы требуют freeShort >= B_min:

```text
minimum: D = B_min
all:     D = freeShort
buffer:  D = max(B_min, freeShort - B_min)
```

Buffer оставляет целую следующую корзину только при freeShort >= 2*B_min. Это не гарантия финансирования следующего draw в бедном резерве.

При h_e=1 начальный допуск одного билета 20%, при h_e=3 — 10%; потолок остаётся 40%. Более высокий допуск лучше заполняет корзину, но может сократить число draws, поскольку каждый из них расходует больше. K=5 легче заполняется и чаще запускается, но равные $5-призы не отвечают сами по себе приоритету крупных номиналов. Этот тест не выбирает окончательную форму корзины.

Это объясняет преимущество buffer как простого исследовательского baseline, но не доказывает его оптимальность для всех потоков.

## Без стартовой субсидии и незавершённое ожидание

Десять разных призов, h_e=1, buffer. Последний столбец — время от последнего draw до конца недели (если draws не было — всё окно); это нижняя граница ещё не завершённого интервала, а не уже измеренный будущий срок следующего draw.

Резкое прекращение торговли оставляет длинный хвост без draws, несмотря на короткие интервалы между первыми розыгрышами. Поэтому p95 только завершённых интервалов может выглядеть хорошо и скрывать проблему. JSON отдельно хранит хвост, возраст самых старых открытых attempts и число наблюдений метрики. Метрики never-won различают реально участвовавших и всех кошельков, уже получивших attempts.

## Предварительный выбор

Для следующего предметного обсуждения: фиксированная корзина около 10 мест, начальный допуск 20% при текущем cap 40%, D с сохранением одной минимальной корзины при достатке денег. Это рабочий кандидат, не утверждённая настройка. Приоритет регулярности делает его интереснее all; приоритет максимального разового выигрыша может оправдать all.

Результат не обещает четыре выплаты в сутки новому токену. При $20k суточного оборота Short получает условные $45 в сутки: полностью восполнить $110 требует около 59 часов. В варианте без банка получилось примерно два draws за неделю. При $200k поступает $450 в сутки — уже хватает примерно на четыре минимальные корзины по $110. Настройки шансов не изменяют этот денежный предел.

Нужно ещё отдельно проверить корзину на 5 мест с крупными/мелкими призами, другие численности аудитории и чувствительность к реальному effective revenue. Здесь кошельков всегда 60, максимум 20 seeds, нет confidence intervals; нельзя объявлять победителя по небольшим разницам средних. h_l=6 и cap=40% не сравнивались. Не строим вывод о прибыльности farming или безопасности RNG.

## Воспроизведение и проверки

```powershell
npm run test:short:sweep
npm run report:short:sweep
python scripts/short_sweep.py --seeds 20 --output research/short-sweep.json
```

[Скрипт](../scripts/short_sweep.py), [тесты](../test/short-sweep.test.py). Полный JSON генерируется локально и исключён из Git; все таблицы выше рассчитаны из него. Поля метрик содержат mean/p10/p50/p90 и число наблюдений; это эмпирические квантили прогонов, не доверительные интервалы. gap_p95 усредняет внутрипро́гонные p95, prize_median — внутрипро́гонные медианы, не объединённые распределения.

Проверены 4 новых sweep-теста и все 16 существующих Short/economy тестов. На каждом временном шаге каждого прогона проверяются сохранение денег и carry, входные события одинаковы для политик одного seed. Контрактные тесты повторно не запускались: контракты не менялись.
