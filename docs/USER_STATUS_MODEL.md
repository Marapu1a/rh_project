# Статусы для будущего сайта

29.09.2026. Это описание отображения. [API покупок/билетов](USER_STATUS_API.md) реализован локально; frontend и API результатов/выплат ещё не реализованы.
Основа — [пользовательские правила](USER_RULES.md). Статусы разных сущностей нельзя
сливать в один индикатор «успех»: успешный swap не доказывает наличие билета или приза.

| Сущность / статус | Что показываем и чем подтверждаем |
|---|---|
| Покупка: ожидает подтверждения | Hash транзакции, сеть; ещё нет подтверждённой учитываемой покупки |
| Покупка: подтверждена, ожидает обработки | Receipt успешен, но индексер ещё не дошёл до нужного блока или ждёт финальности; показываем высоту обработки |
| Покупка: учтена | Индексер воспроизвёл поддержанный BUY: адрес, USDG net debit, версия правил, hash/block, добавленные попытки и остаток до следующей |
| Покупка: не учтена | Завершённая проверка с конкретной причиной: неподдержанный маршрут, неоднозначная атрибуция, не BUY, reverted; не подменяем этим статусом RPC failure или незавершённую обработку |
| Билеты: доступны для следующего списка | Раздельно Short/Monthly; покупка меньше порога может увеличить только остаток, без целого билета |
| Билеты: включены в розыгрыш | Конкретные draw ID, cutoff block/hash, snapshot и число включённых попыток; привязка проверяется по данным snapshot |
| Билеты: использованы | Завершён именно этот draw; отдельно Short/Monthly, независимо от выигрыша. Новые попытки вне cutoff не списываются |
| Розыгрыш: ждёт готовности | Конкретная причина: интервал, бюджет, участники, данные/RPC, gas, ETH или RNG; ожидание не является проигрышем |
| Розыгрыш: зафиксирован / обрабатывается | Frozen бюджет и список, RNG request/result; промежуточный допуск не называем победой |
| Результат: награда назначена | Окончательная обеспеченная награда по данным контракта, сумма USDG и адрес; ещё не выплата |
| Выплата: ожидается / отправлена | Неизвестный результат отправки тоже остаётся ожиданием; hash показываем, если известен, не отправляем повтор вслепую |
| Выплата: выполнена | Подтверждённые receipt и состояние выплаты конкретной награды; ссылка на транзакцию |

Если исход без победителя — показываем завершённый draw и возврат/перенос бюджета,
а не ошибку выплаты. Дорогой gas или неудачный Claim не аннулирует назначенный долг.
При реорганизации сети данные до принятой границы подтверждения могут пересматриваться;
не называем наблюдение worker контрактной гарантией финальности.

Индексер даёт атрибуцию и расчёт билетов, dataset — включение, on-chain accounting —
назначение и погашение награды. Будущий API должен давать эти основания и время
обновления, а при недоступном источнике показывать устаревшие данные/ожидание,
не нулевой баланс и не выдуманное «не учтено». Эти требования реализуются вместе
с постоянным индексером и сайтом; данный пакет их не объявляет готовыми.
