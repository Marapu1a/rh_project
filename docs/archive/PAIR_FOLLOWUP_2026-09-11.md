Дата: 11.09.2026. Продолжение [первого recon](PAIR_TECHNICAL_RECON_2026-09-11.md). Только чтение сети и публичных данных; транзакции не подписывались и не отправлялись.

Переданная пользователем [сводка](../../research/2026-09-11-user-handoff.txt) в основном повторяет первый recon. Новых исходников или примеров collect/claim в ней нет. Принимаем направление дальнейшего исследования: один TOKEN/USDG рынок, проверка fee path и RH-VRF как первый кандидат. Это не подтверждение совместимости и не выбор production randomness.

**Новые чтения сети**

Запросы eth_call выполнены на одном блоке `0x3968473`. URL RPC, calldata и сырые ответы сохранены в [снимке](../../research/2026-09-11-followup-rpc.json).

| Контракт / чтение | Ответ | Что это доказывает |
| --- | --- | --- |
| Launchpad `launchFeeWei()` | `500000000000000` wei = **0.0005 ETH** | Текущее значение getter; не полную стоимость будущего запуска |
| Launchpad `owner()` | `0x3da42dbecbeff476c027f8298bfad0d6c3ba5656` | Адрес owner, но не полный набор прав и не тип кошелька |
| Launchpad `launchV2ModeRegistry()` | `0xdacaed317f72d8ff127a732e1b8f1e2d4807bb2d` | Ссылка из текущего состояния; не подтверждение всех release bindings |
| EIP-1967 implementation slot | `0x8000b64b62837a1511e302c62354e1bc39b5641a` | Реализация подтверждена через RPC, а не только Blockscout |
| Исследованный vault `epoch()` | `1` | Только номер эпохи; не момент отнесения комиссий к эпохе |
| Custom coordinator `owner()` | revert | Этот getter не дал ответа; это НЕ доказывает отсутствие администратора |
| RH-VRF `owner()` | `0x801294a07f7b67dcf328ebb4b1430cfd3abbf440` | Адрес owner; независимость операторов этим не проверяется |
| RH-VRF `subscriptions()` | `0x3fbfe73935b729c6a30ae6060d5708215b3633f5` | Совпадает с опубликованной документацией |
| RH-VRF `price(1,150000)` | `160000200000000` wei = **0.0001600002 ETH** | Тариф за один word с указанным callback gas limit на этом блоке |

Состав тарифа RH-VRF: baseFee=100000000000000 wei, perWordFee=200000000 wei, perCallbackGasFee=400000000 wei. Формула соответствует [документации](https://rh-vrf.com/docs). Газ транзакции запроса оплачивается отдельно. Лимит 150000 выбран для сравнения с примером документации, а не измерен на нашем контракте.

Иллюстрация расходов: если проводить 120 коротких и один месячный розыгрыш за 30 дней, запрашивая по одному word с этим лимитом, тариф составит **0.0193600242 ETH**, без газа запросов и других операций. Это сценарий, не обязательный расход: при недостижении порога розыгрыши пропускаются, а тарифы могут меняться.

**Поправка к developer buy**

В сводке приведены нулевые поля API. Они не описывают фактическое исполнение исследованного запуска.

Для [транзакции](https://robinhoodchain.blockscout.com/tx/0xa0e94e585afa21743c69e41b374043ece7c6ea0c76422e9657e8e38c43b63556) eth_getTransactionByHash подтвердил:

- value: **0.00051 ETH**;
- selector: `0xb802af88`;
- developerBuy.ethAmountIn: **0.00001 ETH**, при декодировании по 13-польному launchV2Token tuple из публичного frontend ABI;
- developerBuy.projectAmountOutMinimum: `6028602891762779477267` raw units.

Calldata сохранена в [снимке цепочки](../../research/2026-09-11-followup-chain.json). Ненулевую покупку также поддерживают Swap-события исходного recon. Разница между value и заявленным developerBuy равна 0.0005 ETH и совпадает с текущим launchFeeWei. Но историческое чтение getter на блоке запуска вернуло RPC-ошибку `metadata is not found`, поэтому историческое назначение всей разницы ещё не доказано отдельным чтением состояния.

Следовательно, **developer buy в этом запуске был**, но его обязательность и минимум для будущего запуска остаются неизвестными. Газ не входит в transaction value; сумма 0.00051 ETH не является полной стоимостью операции.

**Что мешает закрыть fee path**

При успешных запросах Blockscout для действующей реализации launchpad, custom coordinator и исследованного vault вернул bytecode без source_code и abi. Proxy при этом имеет опубликованный исходник: верификация proxy не верифицирует бизнес-логику implementation. Часть повторных запросов через другой HTTP-клиент получила 403; это ограничение доступа, не доказательство отсутствия контрактов или исходников.

В публичном frontend bundle есть интерфейсы epoch, claim(asset,uint64), claimable(uint64,address,address), collectFees(uint256), NativeFeesCollected и событий claims. Эти фрагменты помогают строить проверочные чтения, но **не подтверждают ограничения и экономику текущего custom release**. Подменять ими недоступные исходники нельзя.

История token transfers через explorer в этой попытке недоступна (403). Ограниченный eth_getLogs по исследованному vault и RH-VRF за последние 10000 блоков вернул пустой массив. Это не доказывает отсутствие более ранних collection/fulfillment операций. Полный исторический поиск ещё не выполнен.

**Какие материалы действительно сократят дальнейшую работу**

1. Ссылка на исходники или verification/Sourcify record **implementation** `0x8000…641a` и custom coordinator `0xacda…67a9`, а также актуальный release manifest с ABI. ABI самого proxy недостаточно.
2. Адрес токена, подтверждённо выпущенного через текущий custom coordinator, и хотя бы одна транзакция collect/claim его creator revenue. Исследованный ранее токен возвращает policy canonical=false и не доказывает свойства текущего custom release.
3. Ранее найденные материалы по RH-VRF: исходники verifier, аудит, операторы, правила смены ключей, успешные fulfillment транзакции и testnet адреса.

Дальше остаются те же проверки: действующий release → фактическая комиссия → получатель/активы/claim; затем attribution маршрутов и тестовый цикл randomness. Никакие коэффициенты наград или production-контракты на основании этих неполных сведений не утверждены.
