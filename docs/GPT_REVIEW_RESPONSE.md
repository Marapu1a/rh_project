## Конкретная мелкая находка

Это явно закреплено `test/pons-delay-status.test.cjs` после удаления трёх причин. В частности, штатное `transactionLimit` исключено из причин, поэтому оператор может видеть одновременно `status: waiting` и `operational.state: clear`. Инструкция `scope` частично ограничивает смысл clear, но два поля остаются противоречивыми. Минимально: при `report.status==='waiting'` всегда отдавать `state:'waiting'` (пустой список причин допустим или отдельный нейтральный код budget/poll); тестировать этот случай и `transactionLimit`. ## Dependency audit: где риск достижим

Опубликованный `npm audit`:20 затронутых пакетов (8 high), не20 отдельных доказанных эксплойтов; advisory срабатывает при конкретном использовании входных данных. Например, у `serialize-javascript` опасная сериализация RegExp/Date, а у `tmp` есть сценарии с параметрами путей и symlink; факт установки сам по себе не показывает такую достижимость. Документальная проверка `require` локального Pons/API входа не загрузила цепочку Hardhat/Mocha/undici/adm-zip, и это уменьшает риск текущего *тестового* процесса. Но `scripts/pons-automation.cjs` вызывает `compile()` из `scripts/compile.cjs`; без пары `RH_TEST_ARTIFACT`/hash эта функция **динамически загружает `solc` и компилирует исходники**. Поэтому формула «все direct зависимости devDependencies» не доказывает, что будущий исполнитель не загрузит toolchain: путь fallback существует.

Перед боевой упаковкой нужна узкая проверка: явная проверенная ABI/artifact supply для runtime без компиляции; отдельный `npm ci --omit=dev`/import-and-start smoke будущих operator/API/site entrypoints в изолированной среде; inventory фактически загруженных модулей после полного прохода, включая fallback; разбор применимости advisories для этих путей, затем точечные безопасные обновления. Не запускать слепой `npm audit fix --force`: предложенный Hardhat3 — major migration, не косметика. Не давать `solc`/Hardhat, который читает файлы/внешние ответы, лишних прав в будущем operator окружении. Это **обязательная граница этапа B**, а не найденный exploit и не причина переписывать тестовый контур сейчас.
