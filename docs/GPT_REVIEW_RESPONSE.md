## Вердикт

Предыдущие две границы существенно исправлены. Контракт больше не принимает
произвольный JSON и caller-supplied `nextHash`: объявление ограничено
`adapterId/fromBlock`, а commitment воспроизводится Solidity и JS одинаково.
`genesisAdaptersHash` связывает начальный ordered список с genesis manifest;
count/currentHash/lastFrom обнаруживают пропущенный последний log. Loader
проверяет всю finalized цепочку даже для старого cutoff, но неизвестный id с
будущим fromBlock помечает pending, а с активации **не строит новый dataset**.
Исторический cutoff и старые frozen jobs остаются проверяемыми. Не нашёл пути,
которым корректное typed объявление изменит старый manifest hash или задним
числом пересчитает уже frozen snapshot.

Отсутствие public trust теперь по умолчанию ошибка; явный `unadmitted` для
research и старый локальный v1 fixture помечены отдельно. CLI возвращают
policyStatus отдельно от ledger/artifact hash. Это честная граница: один только
успешный `--verify` сравнивает accounting, поэтому потребитель обязан смотреть
**свой пересчитанный** policyStatus, а не считать совпадение hash аттестацией.

**Остаток не следует называть устранённым:** publisher может напрямую объявить
любой новый ненулевой id, которого пока нет в reviewed decoder. Контракт не
может доказать корректность будущего JS; после activation новые datasets
остановятся, пока не появится совместимый выпуск. Это уже типизированный
доступный для проверки отказ, а не parser poison старого JSON. Нужна ясная
операционная ответственность за ключ и публикацию до activation; автоматический
skip/reset испортил бы публичную историю. При недоступном/лживом RPC проверка
даже старого cutoff по-прежнему может остановиться — сохранение семантики
истории не равно автономному завершению без источника данных.

Расширяемость описана честно: `adapterId = keccak(name)` фиксирует имя
спецификации, **не исполняемые байты**. Версионное имя нельзя переиспользовать;
воспроизводимый release/код verifier и реальные vectors остаются обязательными.
Текущий `extend()` добавляет route к прежнему manifest, а validator сохраняет
router/manager/pool/assets неизменными. Новый router не становится допустимым
из-за typed ABI: ему нужен явный технический формат миграции manifest/trust с
публичной историей. Иная оценка USDG или бенефициар — отдельное продуктовое
решение владельца. Реальных новых BUY adapters этот пакет не добавил.

## Следующий законченный пакет

Поддерживаю **независимый replay сохранённого job перед первым `begin`** как
ближайший шаг. Под scheduler lock заново читать admitted policy на cutoff job,
полную каноническую BUY/lifecycle историю до этого блока и строить artifact;
сравнивать весь snapshot/participants/ranges/request/root/rules, а не только
domain hash и пересчитываемый checksum. До broadcast при несовпадении — stop,
без замены сохранённого job; если on-chain begin уже был, сверять его commitment
и восстанавливать прежний job, не создавать новый. `closeEmpty` уже пересобирает
историю; его путь сохранить. Позитивные vectors: старый frozen job после нового
известного и неизвестного id, delayed finality. Негативные: согласованная
подмена participants+root+snapshotHash+job/state checksums, пропущенный BUY,
orphan cutoff и неизвестный adapter на cutoff нового job.

Публичные source/authority, finality, notice, настоящий venue/RNG и аудит ещё
отдельные релизные решения. Не объявлять нынешний адресный тестовый результат
production готовностью.
