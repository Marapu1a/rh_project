## Fork evidence и следующий минимальный quote path

Сохранённые данные и script согласованы: pool key пересчитан в pool id, router code hash проверен, 10 USDG точно списаны, swap+unwrap в одной tx дали 0.003754920360290634 native ETH до gas, завышенный minOut отвергнут. Используется настоящий Pancake Permit2 `0x31c2…c768`, указанный и [официальной документацией](https://developer.pancakeswap.finance/contracts/permit2/addresses). Это сильное подтверждение **исполнимости конкретного маршрута на локальном fork**. Проверка не измеряет газ Nitro/L1-data, не доказывает исходники/immutables и не даёт production quote: USDG тестового EOA внесён через storage override, а trial quote использует snapshot и реальную локальную tx. Выводы документа здесь соразмерны evidence.

Не нужно воспроизводить trial transaction в публичном worker. Минимальный read-only путь для этого неизменного pool/key: после pinned USDG→Permit2 и Permit2→router allowances выполнить `eth_call` **точно того же** `router.execute` от ops EOA на фиксированном blockTag с пробным `minOut` в обоих местах calldata. Router не возвращает output, но успешный call доказывает, что output ≥ заданного порога, revert — нет (сначала отличить прочие ошибки по low-min probe). Ограниченный поиск по minOut вокруг оценки из состояния пула/последней успешной котировки даёт консервативную нижнюю границу; если уложиться в малое число проб не удалось — ждать, не отправлять. Затем `estimateGas` точного calldata, cap по ETH/gas, проверка свежего block перед send; уже при отправке тот же minOut/deadline ограничивает изменение состояния и MEV. Это кандидат, который требует адресного read-only RPC/fork теста, а не утверждение, что eth_call возвращает котировку. Если найдётся подтверждённый Infinity quoter с совместимым pool key и deployment pins, можно выбрать его после такой же проверки. Не подменять executable minOut spot-ценой из `slot0`.

Следующий действительно опасный кусок — journaled approve/Permit2 allowance/swap под **одним** ops signer/nonce с refill: каждый неизвестный send сначала сверять по сохранённому intent/hash/receipt, затем измерять фактический native output и только после этого разрешать существующий refill. Неизрасходованные allowances ограничить и учитывать при restart. Призовую казну и публичный gate не затрагивать.
