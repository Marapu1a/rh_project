## Что хотим получить

Первый запуск остаётся на PAIR / Robinhood Chain. Нам нужна простая система, которую можно независимо развернуть на другой совместимой площадке, адаптировав сбор комиссий и правила финансирования под её экономику.

Не ставим целью найти личности администраторов PAIR или устранить любой внешний риск. Полномочия интересуют только через конкретные последствия: остановка дохода, доступность старых claims, работоспособность торговли. Повторный запуск не должен требовать разрешения PAIR.

Не обещаем перенос существующих LP, токена, holders, резервов или обязательств. Не добавляем ради переносимости proxy, governance, emergency withdrawal, arbitrary calls или универсальный framework. Деньги основной призовой казны нельзя забрать на новый запуск.

## Что накопали

- Sourcify **API v2** отдал verified sources, хотя старые repository URL отвечали 404, а Blockscout — 403. Для семи deployments получен `exact_match`, runtime из Sourcify побайтно совпал с RPC на блоке **63405715**, chain **4663**. Проверены hashes сохранённых source-файлов по metadata. Независимого solc rebuild не было.
- VaultV2 получен из verified compilation FactoryV2, которая создаёт его через `new ...{salt:...}`. Отдельный будущий vault нашего проекта ещё не проверен. Исторический public vault `0xd1ade…` не идентифицирован как этот V2.
- FactoryV2 не обновляет vault implementation: соответствующая функция всегда revert. В изученном VaultV2 нет вывода/передачи LP или произвольного вызова. Это вывод об этой ветке, не всей инфраструктуре PAIR.
- Fee-sharing mode 1 допускает community takeover. Registry может сменить recipients без подписи прежних получателей. Atomic transition собирает fees старого epoch до переключения; старые claimable не переписываются.
- VaultV2 распределяет collected fees 70% creator / 30% protocol. Protocol переводится treasury сразу: ошибка этого transfer откатывает collect. **Это не 70% торгового оборота и не доказательство effective revenue 0.5% оборота.**
- Legacy PairV4Locker — отдельный механизм с credits обеих сторон; не custody native V2 позиции.
- Native hook swap callbacks не используют серверный priceSigner. В beforeSwap есть чтение on-chain stateView; токен, PoolManager, сеть и прочие зависимости не исчезают.
- Launchpad upgradeable, канонический `launchV2Token` выбирает registry и его currentCoordinator. Выбранный registry сверили через proxy. Старый `launchV2Coordinator()` обслуживает другой маршрут: несовпадение этих адресов не означает поломку канонического запуска.

## Что означает это для нашего кода

- FeeRouter уже конкретно привязан к PAIR vault/position API. Это не реализованный универсальный fee adapter. Одноразовый bind и epoch guard сохраняем; source failure / epoch drift блокируют rollover. Уже начисленные recipient credits не требуют успешного rollover для выплаты. Успешная rollover transaction остаётся бухгалтерской границей кампании.
- PromoVault не вызывает PAIR. Token, quote, controller и nextStartTarget immutable и задаются при deployment. Но GENERAL **3:2:1** и overflow Next → Current зашиты в код: другие пропорции сейчас требуют новой версии, а не настройки старого экземпляра.
- External funding не создаёт project fee; direct USDG учитывается как GENERAL; free, frozen/reserved и claimable разделены. Старые обязательства не превращаются в доступный бюджет нового deployment.
- Production conversion, indexer, RNG/controller и полный Short pipeline ещё отсутствуют. DrawControllerFixture — тестовая заглушка, не безопасный production controller. Локальная модель розыгрыша не равна реализации в сети.
- USDG остаётся призовым номиналом текущего продукта. Quote address технически параметризован, но смена актива — отдельное продуктовое решение; decimals и target raw units проверяются заново. Текущая сборка нацелена на Cancun, совместимость другой EVM нельзя предполагать.
